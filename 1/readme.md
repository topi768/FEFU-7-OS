# Сборка и запуск проекта в Windows

Команды выполняются в PowerShell из папки проекта, где лежит `CMakeLists.txt`.
Для этого способа сборки должны быть доступны CMake, G++ и `mingw32-make`.

## 1. Подготовка сборки

```powershell
cmake -S . -B build-windows -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Debug
```

Эта команда читает описание проекта из `CMakeLists.txt`, проверяет компилятор и создаёт правила сборки.
Наша программа `hello.exe` на этом этапе ещё не создаётся. При проверке компилятора CMake может собирать небольшие служебные программы.

### `cmake` — запуск CMake

CMake подготавливает правила сборки по описанию проекта. Саму компиляцию затем выполняет компилятор, вызываемый инструментом сборки.

### `-S .` — папка исходного проекта

`-S` задаёт папку, в которой CMake ищет основной `CMakeLists.txt`.
Точка `.` означает текущую папку терминала. Поэтому перед выполнением команды нужно перейти в папку проекта.
Если терминал открыт в другой папке, точка будет обозначать уже её.

### `-B build-windows` — папка сборки

`-B` задаёт папку для автоматически создаваемых файлов. Здесь это `build-windows` внутри текущей папки.
Если такой папки нет, CMake создаст её.

В ней будут храниться настройки CMake, правила сборки, промежуточные файлы и готовая программа.
Исходники остаются отдельно от результатов сборки.

Название `build-windows` выбрано нами: это не специальное слово CMake.
Если изменить его, новое имя нужно использовать и в последующих командах.

### `-G "MinGW Makefiles"` — генератор правил сборки

`-G` выбирает генератор — формат, в котором CMake создаст правила сборки.
`"MinGW Makefiles"` означает подготовку файлов правил для инструмента MinGW Make (`mingw32-make`).
Кавычки нужны, потому что название содержит пробел и должно передаваться как один аргумент.

Генератор не устанавливает компилятор и MinGW Make: они должны быть установлены заранее.

### `-DCMAKE_BUILD_TYPE=Debug` — конфигурация для отладки

`-D` означает «задать переменную CMake». Имя переменной здесь — `CMAKE_BUILD_TYPE`, её значение — `Debug`.

Для выбранного генератора это включает конфигурацию сборки для отладки.
При использовании GCC она обычно добавляет отладочную информацию: GDB сможет связывать выполнение программы со строками исходного кода и показывать переменные.
Эта настройка сама не запускает отладчик и не устанавливает точки остановки.

Стандарт языка задаётся отдельно, в `CMakeLists.txt`. В нашем проекте используется C++98:

```cmake
set(CMAKE_CXX_STANDARD 98)
```

### Как понять, что подготовка завершилась

При успешном выполнении CMake обычно выводит `Configuring done`, `Generating done` и путь к файлам сборки.
После этого можно переходить к следующей команде. При появлении ошибки сначала нужно устранить её.

## 2. Сборка программы

```powershell
cmake --build build-windows
```

Эта команда означает: «Собери проект по правилам, подготовленным в папке `build-windows`».

- `cmake` — запустить CMake.
- `--build` — выполнить сборку.
- `build-windows` — использовать указанную папку с подготовленными правилами.

CMake вызывает выбранный инструмент сборки — в нашем случае MinGW Make. Тот запускает G++ и необходимые инструменты.

Сборка включает два основных действия:

1. **Компиляция:** исходный текст `main.cpp` преобразуется в промежуточный объектный файл с машинным кодом.
2. **Компоновка:** объектный файл соединяется с необходимыми библиотеками, и получается исполняемый файл `hello.exe`.

Для нашего проекта с `add_executable(hello main.cpp)` и без дополнительных настроек вывода результат находится в `build-windows\hello.exe`.

При повторной сборке инструмент обычно пересобирает только изменившиеся части.
После изменения `main.cpp` обычно достаточно снова выполнить команду сборки.

## 3. Запуск программы

```powershell
.\build-windows\hello.exe
```

Это запуск готового исполняемого файла из PowerShell:

- `.\` — начать путь с текущей папки.
- `build-windows\` — папка с результатами сборки.
- `hello.exe` — имя запускаемой программы.

Эта команда ничего не компилирует. Если изменить исходники, но не пересобрать проект, запустится предыдущая собранная версия.

Ожидаемый вывод:

```text
Hello world!
```

Порядок действий: подготовить правила сборки → собрать программу → запустить готовый файл.
